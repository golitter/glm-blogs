# AI 自进化与 RSI：Coding Agent 速记

## 1. 核心概念

- **AI 自进化**：系统通过经验和反馈，对自身模型、Harness、记忆或策略等进行持续修改，并保留经过验证的有效变化，以提升后续表现或效率。
- **RSI（递归自我改进）**：系统产生的自身改进被继承到后续改进过程，使升级后的系统继续参与自身改进。宽泛定义强调递归反馈；更严格的元改进定义强调产生、验证、选择后续改进的机制本身也成为改进对象。

```text
S₀ 改进自身 → S₁ → S₁ 使用升级后的能力继续改进自身 → S₂
```

RSI 的定义存在不同口径，本文采用以下三层分析框架：

1. **持续自进化**：系统能利用反馈更新自身。
2. **结构性递归改进**：更新后参与产生、验证或选择后续改进的能力或机制，被用于下一轮自身改进。
3. **有效递归元改进**：在上述闭环基础上，有独立证据证明更新后的系统更擅长产生有效改进。

**三者不可直接等同。** 不能只凭任务涨分认定元能力增强，也不要求每轮所有指标同时上涨。[参考：递归结构与有效性的区分](https://arxiv.org/html/2609.11873v1)

同一个 Agent 可以既执行任务又改进自身。判断递归时，要检查升级是否进入下一轮改进过程；仅由固定的外部优化器持续升级执行器，不足以证明执行器的元能力增强。

## 2. Task 与 Meta benchmark 到底测什么

| 视角 | 测试任务 | 评价对象 |
|---|---|---|
| Task | 修复 issue | Agent 完成外部任务的能力 |
| Meta | 在规定预算下改进 Agent 的模型或 Harness | Agent 产生有效改进的能力 |

**Meta benchmark 是“改进任务集合 + 预算与操作约束 + 验证和评分规则”。** 本文用这个名称表示元能力评测，不特指某个统一的标准数据集。

Meta benchmark 评估的是 Agent 在标准化条件下产生有效改进的能力；它本身并不要求被改进对象一定是 Agent 自己。**若要证明 RSI，还必须另外验证真实的自我改进与跨轮继承闭环。**

以当前 Agent 漏跑测试为例：

1. **失败日志**：发现它经常漏跑相关测试——这是改进材料。
2. **元任务**：要求它分析日志，在最多 20 次实验内修改自身 Harness——这是一次改进任务。
3. **效果评估**：用未参与调优的 issue 检查修复率、回归率和成本——判断本次修改是否有效。
4. **Meta benchmark**：把多个这样的改进任务及其评测规则组织起来——评测改进能力。

**当前问题可以提供题目，但失败日志本身不是 benchmark；一次修改有效，也不等于元能力比上一代更强。** 同一个系统接受 Task 和 Meta 两种评测，无须生成两个版本再融合。

## 3. Harness 侧：实际怎么改

Agent = **LLM + Harness**。Harness 是提示词、规划、工具调用、测试、重试等运行流程，也可以包含自我改进流程。以下是示意流程，不是已验证的实验结果。

固定模型权重：

```text
用 H₀ 做任务 → 分析失败 → 修改自身 H₀ → 开发验证 → 保留有效的 H₁
```

执行任务时修改的是用户项目代码；自我改进时修改的是 Agent 自己的 Harness。**不需要先修改 Task benchmark，也没有必须先改任务流程、再改自我改进流程的顺序。**

- 给自己加入“修改后运行相关测试”，可能提高修复率：这是任务能力改善。
- 当 Agent 主导提出并实施对自身改进流程的修改，并由升级后的流程实际负责后续改进时，就形成了改进机制层面的递归反馈。仅仅增加任务测试或修改普通执行策略，不足以证明改进机制已经进化。
- 新流程是否真的让改进更有效、更省资源：需要元能力评测验证。

```text
S₀ = LLM + H₀
S₀ 修改自身 H₀ → S₁ = LLM + H₁
S₁ 使用 H₁ 的流程继续修改自身 → S₂ = LLM + H₂
```

被评测的是整个 Agent 的改进能力，不是脱离模型的 Harness。

## 4. 模型侧：实际怎么改

本例固定 Harness，只更新模型权重：

1. 使用 M₀ 的 Agent 分析自身失败记录，设计训练数据与训练方案。
2. 经训练工具得到 M₁，用隐藏任务验证任务表现与成本。
3. M₁ 接替 M₀，参与下一轮自身训练改进，产生 M₂。
4. 另外评估 M₁ 是否比 M₀ 更能提出、验证和实现有效训练改进。

**训练后任务涨分不自动证明 RSI；新模型需要参与后续自身改进，元能力增强也需要独立证据。** 固定另一侧是便于归因的实验设定，不是模型侧 RSI 的唯一形式。

模型与 Harness 同时更新是协同改进；只有升级反馈到后续自我改进过程，才涉及协同 RSI。

## 5. 如何比较元能力，如何防过拟合

- **本轮有没有改好**：围绕当前问题，独立检验修改收益。
- **新版本是否更会改**：在可比改进任务与资源预算下比较。可让新旧 Agent 分别改同一份历史系统的副本；这是可选对照方法，不是 RSI 必需流程。目标副本用于比较，并不替代真实的自身改进闭环。
- **为什么不能直接比每轮涨幅**：S₀ 改 S₀、S₁ 改 S₁，起点和剩余改进空间不同，涨幅不能直接代表元能力高低。
- **Meta 集不必每轮更换**：固定任务便于比较，新问题可补充为挑战集；更换题集后不能直接比较总分。
- **隔离调优与最终测试**：历史案例一旦用于训练或反复调优，就属于开发材料；保留未用于调优的改进案例和隐藏效果测试，排查重复与答案泄漏。
- **多次运行、独立评分**：记录任务收益与全部改进成本，防止偶然涨分；评价器被修改时，仍需独立依据验证收益。

**能改自己、改完任务更强、比以前更会改自己，是三个需要分别举证的结论。**
