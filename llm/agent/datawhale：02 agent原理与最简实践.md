主流agent架构：

- ReAct：Reason ＋ Action（推理＋行动），每一轮对话先进行思考推理，采取行动，之后根据行动结果进行观察，一轮中可能要经过多次该操作。
- Plan and Solve：规划＋求解，先指定详细的计划和步骤，之后按照步骤来进行操作
- Reflection：反思，执行->反思->优化，主要在于agent的评估。

ReAct适合调用工具的agent；Plan and Solve适合长远规划、复杂度高的任务；Reflection适合对精度要求高的任务。



ReAct架构的手动实现细节：

1. 采用**分层架构**设计，将agent每个模块进行拆解之后单独实现，结构清晰，易于维护。
2. 大模型输出不够规范的处理。llm的输出可能存在格式问题，因此需要一个全面的解析机制。
   - 多层匹配：使用正则等进行格式化解析
   - 容错设计：当不能够解析成格式化时的操作，例如过滤空白字符、转换`'`、`"`为统一的符合，或者llm重新尝试`retry`。
   - 格式兼容：既可以进行复杂格式化，但是当复杂格式化难以处理时，可以支持相对简短的格式化处理。
3. 其他细节：系统提示词的设计、优化。agent的最大尝试次数等。
