目前对应agent的定义还没有一个清晰的概念，可以是调用多次llm api的函数，也可以是调用工具解决问题的应用。

agentic用来描述“像不像一个能自主决策、行动并负责结果的智能体。

agentic system可以分为两大类系统：

- 工作流（workflow）：通过预定义路径编排llm和工具。
- 自主智能体（auto agent）：llm动态控制决策和工具使用，自主规划任务。

工作流侧重于流程固定和可预测性。

自主智能体侧重灵活、自我决策。



智能体系统的基础是具备**检索、工具使用和记忆能力的增强性llm。



## 工作流

- 提示链：按顺序拆分，每一步可能会调用llm api。

  e.g.：调llm api，处理生成内容，编程处理出重要信息 ... 线性产生多次，得到总的结果。

- 路由：根据输入分类，分配给专门的后续任务处理流。

  e.g.：一个通用llm api，处理出来输出，根据输出选择特定任务llm api再次进行处理得到结果。

- 并行：同时执行多个任务，最后进行合并结果

  e.g.：内容检测场景：有多种不同的标签（歧视、辱骂等），并行处理多个不同种类的检测任务，之后进行汇总。

- 协调者-工作者：仔细进行任务拆解，子任务调用llm进行处理。

- 评估-优化：llm产生内容-》llm反馈内容 这样进行循环。

一个工作流往往会用到上面的几种模式，往往是根据实际情况进行使用。

工作流设计需要避免过度复杂性。针对具体问题，使用裸api进行设计。
