> bug复盘：
>
> > # Git 推送 GitHub TLS 握手失败 - 问题复盘
> >
> > ## 一、现象
> >
> > - `git push/pull` 报 `TLS handshake failed` / `unexpected eof while reading`
> > - Claude 插件报 `ECONNRESET` / `ConnectionRefused`
> > - 浏览器能正常上网
> >
> > ## 二、根因（三层叠加）
> >
> > | 层级 | 问题                       | 说明                                                         |
> > | ---- | -------------------------- | ------------------------------------------------------------ |
> > | 1    | **系统级环境变量残留代理** | 注册表写死了 `HTTP_PROXY=http://127.0.0.1:7890`，Git 启动自动读取，强制走代理 |
> > | 2    | **Clash 空配置空转**       | Clash 进程在跑、端口开着，但当前配置没有任何节点，等于空壳   |
> > | 3    | **Git SSL 配置冲突**       | 同时配了 `schannel` 和 `openssl` 两个 sslbackend，导致 TLS 握手异常 |
> >
> > ## 三、关键误区
> >
> > **"系统代理"和"环境变量代理"是两套独立机制：**
> >
> > - 系统代理（注册表）→ 浏览器、GUI 软件 → 看 Clash 的"系统代理"开关
> > - 环境变量代理（http_proxy）→ Git、curl、npm → 看系统环境变量
> >
> > 你关了 Clash 的系统代理 → 浏览器不走代理了，但 Git 只认环境变量，还是在走那个空转的 7890 端口。
> >
> > ## 四、排查时间线
> >
> > 1. 看到 TLS 错误 → 以为是网络问题（误导）
> > 2. 给 Git 配代理 → 没用（误导）
> > 3. 发现系统代理关了 → 以为"代理没开"（误导）
> > 4. **发现环境变量里写死了代理** → 关键突破
> > 5. **发现 Clash 配置是空的** → 关键突破
> > 6. curl 直连 GitHub 返回 200 → 确认网络本身没问题
> > 7. 清理环境变量 + 清理 SSL 配置 → 解决
> >
> > ## 五、修复动作
> >
> > - [x] 清理当前会话代理环境变量
> > - [x] 清理 Git 全局代理配置
> > - [x] 统一 Git SSL 后端为 openssl
> > - [ ] **待办**：删除系统级残留环境变量（Win+R → sysdm.cpl → 环境变量 → 系统变量 → 删除 HTTP_PROXY / HTTPS_PROXY / ALL_PROXY）
> >
> > ## 六、经验教训
> >
> > 1. TLS handshake failed 不一定是网络问题，也可能是 Git 配置冲突或代理空转
> > 2. curl 能通但 Git 不能通时，问题一定在 Git 本身
> > 3. Clash 端口开着 ≠ 代理能用，一定要确认有节点且节点能连
> > 4. 排障先清环境变量和 Git 配置，确认基线再叠加测试
