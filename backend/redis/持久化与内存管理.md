# 持久化与内存管理：重点摘要

---

## 1. RDB 快照

- 全量二进制快照，恢复速度最快
- 触发方式：自动（`save` 配置）、`BGSAVE`（推荐）、`SAVE`（阻塞，禁用）
- **COW 机制**：fork 后共享内存页，主进程修改时才复制，额外开销 ≈ 修改量

| 配置格式 | 含义 |
|---------|------|
| `save 3600 1` | 1 小时内 ≥1 次变更触发 |
| `save 300 100` | 5 分钟内 ≥100 次变更触发 |
| `save 60 10000` | 1 分钟内 ≥10000 次变更触发 |

- 三条规则是 **OR** 关系，满足任一即触发
- **SAVE vs BGSAVE**：SAVE 阻塞主线程；BGSAVE fork 子进程后台执行

---

## 2. AOF 日志

- 逐条记录写命令，追加写入，数据更安全
- 恢复时逐条重放，速度比 RDB 慢

| fsync 策略 | 数据安全 | 性能 | 推荐 |
|-----------|---------|------|------|
| `always` | 最高（最多丢 1 条） | 最差 | 极端安全场景 |
| `everysec` | 最多丢 1 秒 | 均衡 | **生产推荐** |
| `no` | 可能丢数秒 | 最好 | 可容忍丢失 |

- **AOF 重写**：精简冗余命令，只保留最终状态。fork 子进程执行，不阻塞主线程
- 重写触发：文件比上次重写后增长 100% 且 ≥64MB

---

## 3. 混合持久化

- Redis 4.0 引入，AOF 重写时前半段用 RDB 格式、后半段用 AOF 增量
- 开启：`aof-use-rdb-preamble yes`（需先开启 AOF）

| 维度 | 纯 RDB | 纯 AOF | 混合（推荐） |
|------|--------|--------|-------------|
| 数据安全 | 可能丢数分钟 | 最多丢 1 秒 | 最多丢 1 秒 |
| 恢复速度 | 最快 | 较慢 | 快 |
| 文件大小 | 最小 | 较大 | 较小 |

- **AOF 优先级更高**：启动时 AOF 存在则优先用 AOF 恢复

---

## 4. 内存淘汰策略

- 内存达到 `maxmemory` 上限时决定淘汰哪些 Key

| 策略 | 行为 | 场景 |
|------|------|------|
| **`allkeys-lru`** | 所有 Key 中淘汰最久未用的 | **通用缓存首选** |
| `allkeys-lfu` | 所有 Key 中淘汰频率最低的 | 热点明显的缓存 |
| `volatile-lru` | 仅有过期时间的 Key 中淘汰 | 混合持久化+缓存 |
| `noeviction` | 拒绝写入 | 数据不能丢 |

- **LRU**：按最近访问时间淘汰；**LFU**：按访问频率淘汰（Redis 4.0+）

---

## 5. 内存优化

| 数据类型 | 小数据编码 | 转换阈值 |
|---------|----------|---------|
| Hash | ziplist | >512 entries 或 value >64B |
| Set | intset | 非全整数 或 >512 元素 |
| Sorted Set | ziplist | >128 entries 或 value >64B |

- `OBJECT ENCODING key` 查看底层编码
- `MEMORY USAGE key` 查看内存占用
- `INFO memory` 中 `mem_fragmentation_ratio` 理想值 1.0~1.5

---

## 易错点提醒

- **`docker restart` ≠ `docker rm`**：restart 不丢数据，rm 后重建没挂载卷才会丢
- `CONFIG SET` 只运行时生效，重启后失效；永久生效需改 `redis.conf`
- `SAVE` 在生产环境绝对不要用，会阻塞所有请求

## 面试速查

| 问题 | 答案 |
|------|------|
| RDB vs AOF？ | RDB 全量快照恢复快但可能丢数据；AOF 逐条记录更安全但恢复慢 |
| 生产推荐？ | AOF（everysec）+ RDB 混合持久化 |
| AOF 重写原理？ | fork 子进程，只保留最终状态命令，新命令同时写旧文件和重写缓冲区 |
| 8 种淘汰策略怎么选？ | 纯缓存 → `allkeys-lru`；部分数据不能丢 → `volatile-lru` |
| ziplist 何时转 hashtable？ | Hash: >512 entries / >64B value；ZSet: >128 entries / >64B value |
| 内存碎片率怎么看？ | `INFO memory` → `mem_fragmentation_ratio`，理想 1.0~1.5 |
