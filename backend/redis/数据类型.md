# 数据类型：重点摘要

---

## 大小写规则

| 项目 | 是否区分 |
|------|---------|
| 命令（SET/set） | 不区分 |
| 键（key） | **区分** |
| 值（value） | **区分** |

---

## String

| 要点 | 说明 |
|------|------|
| 底层 | SDS（Simple Dynamic String） |
| 最大值 | 512MB |
| `EX` | 秒级过期，`PX` 毫秒级过期 |
| `NX` | **N**ot e**X**ists，键不存在才设置（分布式锁基础） |
| `XX` | 键已存在才设置 |
| `INCR` | 原子递增，线程安全 |

**典型场景**：缓存、计数器、分布式锁、Session

---

## Hash

| 要点 | 说明 |
|------|------|
| 适合存 | 对象属性，单字段频繁读写 |
| 底层 | 小数据用 ziplist，大了转 hashtable |
| `HDEL` 需指定字段 | `HDEL key field`，不能省略字段名 |
| 删整个键 | 用 `DEL key`，不是 `HDEL` |

**vs String 存 JSON**：Hash 可单字段读写，内存更省，但不能对单个 field 设过期

---

## List

| 要点 | 说明 |
|------|------|
| 底层 | quicklist（ziplist + 双向链表） |
| 有序、可重复 | |
| 队列 FIFO | `LPUSH` + `RPOP`（**进和出要在不同端**） |
| 栈 LIFO | `LPUSH` + `LPOP`（同端进出） |

> **易错点**：LPUSH 从左进，LPOP 从左出 → 后进先出（不是队列）。要先进先出必须用 RPOP。

---

## Set

| 要点 | 说明 |
|------|------|
| 无序、去重 | 重复添加不会多存 |
| `SCARD` | **S**et + **CARD**inality，统计元素个数 |
| 集合运算 | `SINTER`（交集/共同好友）、`SDIFF`（差集）、`SUNION`（并集） |
| 底层 | hashtable 或 intset（全整数时） |

---

## Sorted Set（ZSet）

| 要点 | 说明 |
|------|------|
| 元素 + score | 按 score 排序，元素不重复 |
| 底层 | skiplist + hashtable |
| `ZRANGE` | 升序，`ZREVRANGE` 降序 |
| `ZREMRANGEBYRANK 0 0` | 删排名最低（rank 0 = 分数最低） |
| `-1` | 倒数第一个（最高分） |
| 排行榜核心 | `ZINCRBY` 更新 + `ZREVRANGE 0 N` 取 Top N |

---

## Key 管理

| 要点 | 说明 |
|------|------|
| 禁止 `KEYS *` | O(N) 阻塞，用 `SCAN` 替代 |
| `SCAN` | 分批扫描，游标返回 0 表示结束 |
| `COUNT` 不精确 | 按哈希桶扫描，返回数量不保证等于 COUNT，但**确定性**、无随机性 |
| `DEL` vs `UNLINK` | DEL 同步阻塞，UNLINK 异步（大 Key 推荐） |
| `TTL` | -1=永不过期，-2=不存在，正数=剩余秒 |

**命名规范**：`项目:业务:ID:字段`，用冒号分隔层级

## 面试速查

| 问题 | 答案 |
|------|------|
| 5 种核心数据类型？ | String、Hash、List、Set、Sorted Set |
| SDS vs C 字符串？ | O(1)长度、二进制安全、自动扩容、防溢出 |
| Hash 什么时候转 hashtable？ | field > 512 或 value > 64 字节 |
| 为什么用 skiplist 不用红黑树？ | 实现简单、范围查询方便、并发友好 |
| List 做消息队列的局限？ | 无 ACK、无消费者组、消息不可回溯 |
| 为什么禁止 KEYS？ | O(N) 阻塞主线程 |
| INCR 线程安全吗？ | 是，Redis 单线程执行命令 |
