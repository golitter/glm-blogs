# 阶段一：重点摘要

---

## SQL 执行顺序

```sql
SELECT DISTINCT        -- ⑦ 去重
    d.name,            -- ⑥ 挑列
    AVG(e.salary)      -- ⑥ 计算表达式
FROM department d      -- ① 主表
JOIN employee e        -- ① 连表
    ON e.dept_id = d.id  -- ② JOIN 条件
WHERE e.salary > 5000  -- ③ 逐行过滤，分组前
GROUP BY d.name        -- ④ 分组
HAVING AVG(e.salary) > 10000  -- ⑤ 过滤分组，分组后，可用聚合函数
ORDER BY avg DESC      -- ⑧ 排序，可用 SELECT 别名
LIMIT 10;              -- ⑨ 限制行数
```

- WHERE 不能用别名（在 SELECT 之前执行）
- ORDER BY 可以用别名（在 SELECT 之后执行）
- JOIN 在 FROM 阶段完成，不是独立步骤

## JOIN 类型

| 写法 | 含义 |
|------|------|
| `JOIN` / `INNER JOIN` | 只返回两表匹配的行 |
| `LEFT JOIN` | 左表全保留，右表无匹配填 NULL |
| `RIGHT JOIN` | 右表全保留，左表无匹配填 NULL |
| `CROSS JOIN` | 笛卡尔积 |

---

## 子查询

| 类型 | 用法 |
|------|------|
| 标量子查询 | 返回单个值，用于 WHERE 比较 |
| 列子查询 | 返回一列，配合 IN 使用 |
| EXISTS 子查询 | 关联外层表，有结果返回 TRUE，找到一条就停 |
| 派生表 | FROM 中的子查询，把查询结果当临时表 |

- EXISTS 适合：外层表小、子查询表大、需要关联外层的场景
- IN 适合：子查询结果集小的场景

---

## 聚合与分组

- **聚合函数**：COUNT / SUM / AVG / MAX / MIN，将多行压缩为一个值
- **GROUP BY**：按列分组，每组分别聚合
- **WHERE vs HAVING**：WHERE 过滤行（分组前），HAVING 过滤组（分组后）
- 用了 GROUP BY 后，SELECT 只能写 GROUP BY 中的列 或 聚合函数

---

## 窗口函数

**核心区别：GROUP BY 压缩行（多行→一行），窗口函数展开（行数不变，每行附加计算结果）。**

### 语法

```sql
函数 OVER (PARTITION BY 分组列 ORDER BY 排序列)
```

### 排名函数

| 函数 | 规则 | 示例 |
|------|------|------|
| `ROW_NUMBER` | 严格递增，不重复 | 1, 2, 3, 4 |
| `RANK` | 并列相同，跳号 | 1, 2, 2, 4 |
| `DENSE_RANK` | 并列相同，不跳号 | 1, 2, 2, 3 |

### 其他窗口函数

| 函数 | 作用 |
|------|------|
| `SUM/AVG/COUNT OVER` | 聚合但不压缩行 |
| `LAG(列, N)` | 访问前第 N 行的值 |
| `LEAD(列, N)` | 访问后第 N 行的值 |

### 关键点

- `PARTITION BY` = 分组计算，类似 GROUP BY 但不压缩行
- 加 `ORDER BY` 后，窗口范围变为"从第一行到当前行"，SUM 变成累计求和
- `OVER(ORDER BY ...)` 只管计算逻辑，最终显示顺序由最外层 `ORDER BY` 控制

---

例子：取每个部门薪资最高的人

```sql
SELECT tb.name, tb.dept_name, tb.salary FROM (
    SELECT e.name, d.name AS dept_name, salary,
    ROW_NUMBER() OVER( PARTITION BY e.dept_id ORDER BY salary DESC) AS rn
    FROM employee e
    LEFT JOIN department d ON e.dept_id = d.id
) AS tb
WHERE rn = 1;
```

## UNION / UNION ALL

- `UNION`：合并去重（需要排序，性能差）
- `UNION ALL`：合并不去重（性能好）
- 确定不需要去重时优先用 `UNION ALL`

## 索引基础

### 索引类型

- 主键索引：自动创建，不允许 NULL
- 唯一索引：值不能重复
- 普通索引：基本索引
- 联合索引：多列组合索引

### 索引失效场景

| 场景 | 原因 |
|------|------|
| `LIKE '%张'` / `LIKE '%张%'` | 左模糊，B+ 树无法定位 |
| `salary * 2 > 20000` | 对列做了运算 |
| `YEAR(date) = 2020` | 对列用了函数 |
| `WHERE phone = 138`（phone 是 VARCHAR） | 隐式类型转换，等价于对列用了函数 |
| `WHERE a = 1 OR b = 2`（b 无索引） | OR 中有非索引列 |
| 联合索引跳过最左列 | 不满足最左前缀原则 |

### 核心原理

- B+ 树按字段值从左到右排序，左模糊/函数/运算会破坏排序规律，导致索引失效
- 联合索引按列依次排序（先第一列，再第二列），跳过第一列直接查第二列无法利用排序

---

## LIKE 通配符

| 通配符 | 含义 |
|--------|------|
| `%` | 任意多个字符（包括 0 个） |
| `_` | 恰好一个字符 |

- `LIKE '张%'` → 以张开头，**能命中索引**
- `LIKE '%张'` → 以张结尾，**索引失效**
- `LIKE '%张%'` → 包含张，**索引失效**
- `LIKE '_三'` → 第二个字是三
