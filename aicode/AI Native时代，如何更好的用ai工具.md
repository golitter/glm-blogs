# **Code is cheap**

如何在AI Native，更好的结合ai工具去进行工程开发。、

> 这里的ai工具不仅仅指claudecode、codex这些aicoding，还指LLM-core的工具、软件、脚本等。

LLM是**概率模型**，放任LLM会导致错误累积，直到崩溃。

> 当在交互中发现了错误时，可能在此之前很早就产生了错误逻辑。

LLM的context很宝贵，呈现U形结构，开始、结尾的重要性远大于中间部分。



### 水流理论 + 最小混沌单元

![image-20260704000446474](AI%20Native%E6%97%B6%E4%BB%A3%EF%BC%8C%E5%A6%82%E4%BD%95%E6%9B%B4%E5%A5%BD%E7%9A%84%E7%94%A8ai%E5%B7%A5%E5%85%B7.assets/image-20260704000446474.png)

>  **checkpoint** 类似于里程碑开发里面的**里程碑**

![image-20260704000552787](AI%20Native%E6%97%B6%E4%BB%A3%EF%BC%8C%E5%A6%82%E4%BD%95%E6%9B%B4%E5%A5%BD%E7%9A%84%E7%94%A8ai%E5%B7%A5%E5%85%B7.assets/image-20260704000552787.png)

**水流理论**：不要逐行遥控 AI，而是先定目标和边界，让模型在边界内自主探索；人在 checkpoint 处看计划、证据和风险，决定放行、追问、加料、回炉或止损。

**最小混沌单元**：不要把大任务一次性交给 AI，而是拆成小到可检查、大到可自治的任务单元；每个单元配合 spec / codemap / new-chat，保证上下文干净、结果可验、失败可局部回滚。



### 实践经验总结

![image](AI%20Native%E6%97%B6%E4%BB%A3%EF%BC%8C%E5%A6%82%E4%BD%95%E6%9B%B4%E5%A5%BD%E7%9A%84%E7%94%A8ai%E5%B7%A5%E5%85%B7.assets/2037fff8-2e76-4c20-adaa-e3c62aa832eb.png)

1. 0→1 先收敛目标，1→N 先定位地形。
新项目先把模糊想法揉清楚，存量项目先读历史 spec / codemap。

2. Spec 是外部真相源。
重要决策不能只留在聊天里，要沉淀成可反复回看的活文档。

3. 任务包是 spec 的执行切片。
每次只交给 AI 一个边界清楚、可验证、可回炉的小任务。

4. Checkpoint 是控盘点。
不逐行遥控 AI，而是在关键节点看目标、边界、证据和风险。

5. 转向是必要纠偏。
一旦 spec 冲突、越界或连续验证失败，就要暂停、绕道或回炉。

6. New-chat 用来清理上下文。
诊断阶段噪音太多时，用 spec + handoff 开新 chat 干净实施。

7. “完成了”不等于完成。
必须看验证命令、结果、日志、验收标准覆盖和风险说明。

8. 多层 Safety Net 是工程底线。
自验、自测、他测、CI/巡检、灰度/回滚共同兜底风险。

9. 验收强度按风险分层。
本地 demo 可以轻量验收，线上存量系统必须多层验证。

10. 复述机制有两种用途。
实施前复述用于收敛目标，实施中复述用于刷新模型注意力。



### **代码本身越来越便宜，真正贵的是目标判断、边界控制、验证证据、上线风险和组织责任。**

代码廉价化并不意味着工程纪律消失，而是工程纪律上移。

当 AI 让代码生成成本急剧下降后，代码本身从长期资产变成可快速生成、验证、丢弃和重写的过程材料。新的工程重点不再是节俭代码，而是节俭时间：快速生成、快速验证、快速上线、快速回滚。

因此，质量控制也从源码级审美转向目标、边界、证据和风险控制。工程师的价值结构随之迁移：一线工程师负责切任务包和做 checkpoint，TL 负责 spec 和 codemap，架构师负责设计 Harness 控制面，QA 负责多层 safety net 和真实业务风险兜底。

代码可以廉价，但后果不能廉价。AI Coding 的成熟形态，不是放弃工程纪律，而是把纪律从“手写代码”上移到“边界、证据、灰度、回滚和组织级风险控制”。
